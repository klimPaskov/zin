# UI overhaul lane I11: decision seals and achievement icons (handoff)

**Branch:** `zin/integration-r3`, uncommitted (the lead commits). **Lane row:** [02_plan.md](../02_plan.md), I11.

## Plan

- **A. Decision seals.** Every `GFX_decision_zin_<key>` sprite gets its own 32 × 32 Chancery small round seal (design system §4.2, `iconFamilies.decision`). Subjects come from each decision's name and description. Sheets of 12 round seals on black, cut by detection, masked to a round alpha from each seal's own region, shipped as DDS under `gfx/interface/decisions/zin/<key>.dds`. The apply step rewrites the `texturefile` line of each accepted sprite in the staged `interface/*.gfx` files.
- **B. Achievement icons.** The nine `zin_ach_*` achievements of `common/achievements/zin_deep_past.txt` need `gfx/achievements/<id>.dds`, `<id>_grey.dds` and `<id>_not_eligible.dds` (64 × 64), per `.claude/skills/hoi4-feature-assets/references/achievement-icons.md`.

### B. Achievement icons: blocked on a transparency route

- The skill requires a genuinely transparent colour subject per achievement, then the supplied `achievement_template*.png` and `overlay.png` (SHA-256 checked) and `tools/process_achievement_icons.py`. The gptimage route in this lane returns PNG with no documented alpha guarantee. No background-removal route is configured in this repo (no `rembg`; `.tools/3d_pipeline` has no matting route used for icons), so the skill's transparency fallback has no route.
- Nothing has been generated for achievements. No `gfx/achievements/` files exist. The build still reports `GFX-IMPLICIT` for all 27 achievement DDS.
- Resume: when a background-removal route is named by the maintainer, or gptimage is confirmed to return real alpha (a test image with pixels of alpha below 255 outside the subject), generate one subject per achievement with a transparent-background prompt, then the grey and not-eligible triplets per the reference, then stage to `gfx/achievements/` through a builder module that reads the template hashes.
