Every threshold is read from the mechanic's data (`mech_aenor.json` rates, `mech_regions_dark.json` numbers, `world_tension.json` tiers and sources); the Concord loyalty bands (75, 50, 25) are those of `lib/mech_aenor_script.mjs` and are written once in `aoazNumbers`. A row, meter or panel whose trigger, effect or text no built module defines is left out and named in the build log (`resolveAoaz`); this build leaves out nothing.

Derived values: `zin_aoaz_bar_refresh` (`common/scripted_effects/zin_aoaz_bar.txt`) counts the Houses (footholds 2 or more), the Faithful (footholds 5), Service and the Accord members, and calls the refresh of the row's panel (the Concord average comes from `zin_aenor_ui_refresh`). It runs at start-up for every human player (`on_startup`, through `buildUi`'s start-up lines), monthly through the story module's interface refresh (`data/story_ai.json` uiRefresh, trigger `zin_aoaz_bar_shown`), and on every panel click. Pure formatting: it never changes a mechanic variable.

### Top bar and map interface

| Defect (audit) | Fix |
| --- | --- |
| Value counters over the badge sockets ("999" over the seal and lamp) | `GFX_topbar_alert_bg` was four identical dark discs, so the counts sat on invisible badges and lost vanilla's state rings. New sheet `icons-topbar-badges`: one iron boss with a grey, red, amber or green enamel ring (frames neutral, timeout, pending, done, in vanilla's order). The "999" in renders is the renderer's placeholder; in game the counts are one or two digits inside the 17 px badge |
| Empty resource sockets | ten top bar sprites that were cut from the blank `ui-sockets` cells now have their own emblems from the new sheet `icons-topbar-values` (in the walnut-plaque style of `icons-topbar`): army speed, research speed, construction speed, convoys, faction and no faction, nukes (a sealed fire-pot), achievements (a laurel), dismissed alerts (a bell), attacker speed. All eleven rows carry `luma: free` (emblems cut by their own outline, as the plan rule for emblem rows says) |
| Map-mode buttons on an idea picture | `GFX_mapmode_buttons_(de)selected_small_zin_footholds_map_mode` are the bar's own 20 × 18 slate tiles (pilgrim house, dull iron off, gilt on) in `interface/zin_mapmodes.gfx`; `mech_afrit.mjs` no longer points them at `house_first_light` |
| Date plate shows a Gregorian date | Not a ZIN defect in game: the engine fills `DateText` with its own format, and the calendar module already replaces every month key with the god-months, so the game shows "1 Lumae 1748". The "7:00 29, September 1939" in renders is the static placeholder text of vanilla `topbar.gui`, which the offline renderer draws because it has no engine. The longest ZIN month name (8 letters) is shorter than September, so any date that fits in vanilla fits in ZIN. The age ("4A") is on the Aoaz bar, as calendar spec open question 1 decided. Changing the placeholder needs a `topbar.gui` override, which this lane did not make (below) |
| The Realm button | removed when the bar is built (`AOAZ_BUILT`); the bar carries it |
